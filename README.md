# ddd-dojo

DDD(ドメイン駆動設計)の練習リポジトリ。
日本語の要求文からモデリングし、コード生成するまでの一連の流れを、お題ごとに繰り返す。

## 進め方

1. 日本語の要求文(お題)を用意する
2. ユビキタス言語を抽出する(名詞→エンティティ/値オブジェクト候補、動詞→振る舞い候補)
3. モデリングする
   - エンティティ vs 値オブジェクトの判定(同一性の有無)
   - 集約と集約ルートの決定
   - 不変条件の明文化
   - 必要ならドメインイベントの洗い出し
4. 図示する(Mermaid classDiagramで`model.md`に書く。記法は下記「モデリングの記法」を参照)
5. コードを生成する(まずC#、慣れたらTypeScriptに移植)

## 難易度

- **Lv.1(易)**: 集約1つ、値オブジェクト2〜3種、不変条件1〜2個
- **Lv.2(中)**: 集約1〜2つ+関連、ドメインイベント1つ絡む、状態遷移あり
- **Lv.3(難)**: 複数集約(集約間は識別子参照のみ)、ドメインサービスが必要な業務ルール

## ディレクトリ構成

お題ごとにトップディレクトリを切り、その中に言語別の実装を並べる。

```
ddd-dojo/
  lv1-library-loan/
    docs.md          # 要求文・ユビキタス言語
    model.md          # モデリング図(Mermaid classDiagram)・不変条件表
    csharp/
    typescript/
  lv2-xxx/
    docs.md
    model.md
    csharp/
    typescript/
```

## モデリングの記法

モデリング結果は各お題ディレクトリの `model.md` に、Mermaidの`classDiagram`で書く。

- クラスにステレオタイプを付けて種別を明示する
  - `<<AggregateRoot>>` 集約ルート
  - `<<Entity>>` エンティティ
  - `<<ValueObject>>` 値オブジェクト
  - `<<DomainService>>` ドメインサービス(単一集約では守れない不変条件の実現場所)
- 集約をまたぐ参照は識別子(`〇〇Id`という値オブジェクト)経由にし、実体を直接持たせない
- 不変条件はMermaidだけでは表現しきれないため、図の下に表でまとめる(番号・内容・実現場所)
