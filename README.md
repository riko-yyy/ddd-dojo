# ddd-dojo

DDD(ドメイン駆動設計)の練習リポジトリ。
日本語の要求文からモデリングし、コード生成するまでの一連の流れを、お題ごとに繰り返す。

## 進め方

1. 日本語の要求文(お題)を用意する
2. ユビキタス言語を抽出する(名詞→エンティティ/値オブジェクト候補、動詞→振る舞い候補)
3. モデリングする(SUDOモデリングのS/U/D/Oを`model.md`に書く。記法は下記「モデリングの記法」を参照)
4. コードを生成する(まずC#、慣れたらTypeScriptに移植)

## 難易度

- **Lv.1(易)**: 集約1つ、値オブジェクト2〜3種、不変条件1〜2個
- **Lv.2(中)**: 集約1〜2つ+関連、ドメインイベント1つ絡む、状態遷移あり
- **Lv.3(難)**: 複数集約(集約間は識別子参照のみ)、ドメインサービスが必要な業務ルール

## ディレクトリ構成

お題ごとにトップディレクトリを切り、その中に言語別の実装を並べる。

```
ddd-dojo/
  lv1-library-loan/
    docs.md          # 要求文・ユビキタス言語
    model.md          # SUDOモデリング(S/U/D/O)
    decisions.md      # 検討・決定ログ(モデリング〜実装)
    csharp/
    typescript/
  lv2-xxx/
    docs.md
    model.md
    decisions.md
    csharp/
    typescript/
```

## モデリングの記法

[SUDOモデリング](https://little-hands.hatenablog.com/entry/2022/06/01/ddd-modeling)に沿って、各お題ディレクトリの `model.md` に4つのモデルをセクション分けで書く。

- **S: システム関連図** — 利用者とプロダクトの接点を関連図で示す
- **U: ユースケース図** — ユーザー要求に対するシステムの振る舞いを図または一覧表で示す
- **D: ドメインモデル図** — 属性・制約・関連・多重度・集約範囲をMermaidの`classDiagram`(簡易クラス図)で示す
  - クラスにステレオタイプを付けて種別を明示する: `<<AggregateRoot>>` / `<<Entity>>` / `<<ValueObject>>` / `<<DomainService>>`(単一集約では守れない不変条件の実現場所)
  - 集約をまたぐ参照は識別子(`〇〇Id`という値オブジェクト)経由にし、実体を直接持たせない
  - 不変条件はMermaidだけでは表現しきれないため、D節の下に表でまとめる(番号・内容・実現場所)
- **O: オブジェクト図** — ドメインモデルの具体例を、インスタンスと吹き出し(ルール/制約)で示す

作成順序は決め打ちしない。お題ごとにやりやすい順で進めてよい。

## 検討ログの記法

モデリングでも実装でも、選択肢で迷って決めた事項は各お題ディレクトリの `decisions.md` に時系列で残す。

```
## YYYY-MM-DD: 見出し

- 論点:
- 検討した選択肢:
- 決定:
- 理由:
```
